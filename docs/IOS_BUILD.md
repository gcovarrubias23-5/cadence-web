# iOS build (Capacitor)

The iOS app is a Capacitor wrapper around the same React code. The GitHub Pages preview is unchanged: `npm run build` still builds for `/cadence-web/`.

| Command | What it does |
|---|---|
| `npm run build` | Web build for GitHub Pages (`dist/`, base `/cadence-web/`) |
| `npm run build:ios` | Native web bundle (`dist-ios/`, relative base `./`) |
| `npm run cap:sync` | `build:ios`, then copies it and the plugins into `ios/` |

`npm run check` runs both builds, so CI catches a broken native bundle.

The `ios/` Xcode project is generated by `cap add ios` and committed. It uses Swift Package Manager, not CocoaPods. `ios/App/App/public` and the generated config files are gitignored and rebuilt by `cap sync`.

## Mac steps (Linux cannot build or sign iOS)

1. Install Xcode (current release) and Node 22 or newer. The Capacitor CLI needs Node 22.
2. `npm ci`
3. `npm run cap:sync`
4. `npx cap open ios`: opens `ios/App/App.xcodeproj` in Xcode.
5. In Xcode, App target → Signing & Capabilities:
   - Team: your Apple Developer team.
   - Bundle Identifier: the real bundle ID. It must match `appId` in `capacitor.config.ts` (currently the placeholder `com.cadence.app`) and the app record in App Store Connect.
6. Replace the default Capacitor icon and splash in `ios/App/App/Assets.xcassets` with the Cadence artwork (see `docs/APP_ICONS.md`).
7. Run on a simulator or device, then Product → Archive → Distribute App → App Store Connect.

## Decisions for Gustavo

- Bundle ID: `com.cadence.app` is a placeholder. Pick the real one before the first upload, because changing it later means a new app record.
- The deployment target is iOS 15 (the Capacitor 8 default).
